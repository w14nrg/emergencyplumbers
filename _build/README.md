# emergencyplumbers.london — build notes

Static site for GitHub Pages. Pages are generated by a small Node script (no dependencies) from the files in `_build/`. The generated HTML at the repository root is what GitHub Pages serves. GitHub Pages' Jekyll step ignores folders starting with `_`, so nothing in `_build/` is published.

## Layout

| Path | What it is |
| --- | --- |
| `_build/site.config.json` | **The only place contact details live**: phone, WhatsApp, email, address, legal name, prices, coverage |
| `_build/content/*.mjs` | Page content (one module per group of pages) |
| `_build/assets/` | CSS, JS (postcode checker, click tracking), favicon, social image |
| `_build/build.mjs` | Generator |
| `_build/check.mjs` | Checks run on every build — fails on any KPS/old-site text, broken links, duplicate titles, wrong canonicals, more than one H1, invalid JSON-LD |
| `CNAME`, `googleb347dcd6249648e2.html` | Preserved from the old site, unchanged |

## Commands (Node 18+)

```
node _build/build.mjs              # draft: noindex + draft banner while phone is missing
node _build/build.mjs --release    # production: refuses to run unless phone is set; all checks must pass
node _build/build.mjs --preview DIR  # off-site preview with relative links
```

## Before launch

1. Fill in `phone`, `whatsapp.e164`, `email`, `address`, `legalName` in `site.config.json`.
2. Send a test WhatsApp to the number; set `whatsapp.verified` to `true` only once it reaches the business inbox.
3. Approve prices and set `pricing.approved` to `true` (or edit the bands first).
4. Run `node _build/build.mjs --release`. It must print `All checks passed.`
5. Commit the regenerated files to `redesign`.

## Deploy (only with the owner's approval)

1. Note the current `main` commit (`a2b8faa` at the time of the rebuild) — that is the rollback point.
2. Merge `redesign` into `main` (pull request or fast-forward).
3. GitHub Pages republishes from `main` in a minute or two. Custom domain, DNS and Pages settings are not touched.
4. Check: `/`, the four area URLs, `/robots.txt`, `/sitemap.xml`, `/googleb347dcd6249648e2.html`, a redirect (`/about.html`), and WhatsApp/Call on a phone.
5. In Search Console: submit `https://emergencyplumbers.london/sitemap.xml` and request indexing of the homepage.

## Rollback

`git revert -m 1 <merge commit>` on `main` (or reset `main` to `a2b8faa` and push), and GitHub Pages republishes the old site. Nothing else needs undoing because no settings were changed.

## Redirects

GitHub Pages can't send server 301s. Old URLs (`/about.html`, `/contact.html`, `/booking.html`, `/service.html`, `/team.html`, `/testimonial.html`, `/sla.html`) are small pages with an instant meta refresh plus a canonical to the new URL, which Google treats as a permanent redirect. `/index.html` needs no redirect: GitHub Pages serves it as the homepage, and the homepage canonical points to `/`.
